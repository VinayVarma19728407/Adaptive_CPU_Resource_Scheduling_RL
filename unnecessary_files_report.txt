================================================================================
  SECTION 6 — validation/ FOLDER (ENTIRE FOLDER)
================================================================================
The validation/ folder contains four sub-folders of scripts written to validate
the raw and cleaned dataset files. All of these were run once during dataset
preparation; their findings are already incorporated into the data_cleaning/
scripts.

  validation/data_quality/
    - audit_batch_instance_resource_missing.py: Checks what fraction of batch
      instance rows have null plan_cpu or plan_mem. Prints a null-rate table.
    - audit_batch_task_cardinality.py: Counts unique task_name / job_name
      combinations and checks for duplicate composite keys.
    - integrated_data_validation.py: A 15 KB end-to-end validation that checks
      referential integrity across all four cleaned tables (task, instance,
      machine_meta, machine_usage), prints cardinality statistics, and verifies
      temporal ordering.
    - integrated_data_validation_v2.py: Updated version of the same script after
      a few column renames. The v1 is now superseded by v2.
    - stage1_data_contract_check.py: Quick check that required columns exist in
      each cleaned CSV and that no column is entirely null. First validation gate.

  validation/mismatch_investigation/
    - inspect_unmatched_records.py: Loads cleaned task and instance tables, finds
      instance records with no matching task definition, and prints examples with
      surrounding context.
    - investigate_job_mismatches.py: Investigates cases where the same task_name
      appears under multiple job_names (cross-job task sharing).
    - investigate_job_mismatches_targeted.py: Narrower version targeting a
      specific set of task_names known to appear in mismatches.
    - investigate_job_mismatches_v2.py: Updated version using DuckDB for faster
      processing of the same mismatch patterns. Supersedes v1.
    - investigate_unmatched_keys.py: Broader survey of keys that appear in
      instance splits but not in the task table, or vice versa.
    - trace_machine_2739.py: Traces all records for a specific machine ID
      (machine_2739) across all cleaned tables — written to debug an anomaly.
    - trace_unmatched_source_records.py: Follows specific unmatched source
      records across all four tables to find where they diverge.

  validation/relationship_audits/
    - audit_batch_instance_final_splits.py: Post-split validation that training/
      validation/testing splits respect the declared split ratios and have no
      row overlap.
    - audit_machine_timestamp_alignment.py: Checks that machine telemetry rows
      and task execution records fall within the same timestamp range.
    - audit_machine_usage_relationship.py: Verifies that machine_usage rows can
      be joined to machine_meta on machine_id without orphan records.
    - audit_task_instance_job_relationship.py: Full referential integrity check
      between the task and instance tables on the composite key.
    - audit_task_instance_job_relationship_v2.py: Faster DuckDB version of the
      same referential integrity check. Supersedes v1.
    - finalize_relationship_validation.py: Summary validation run before locking
      the dataset — confirms all checks pass and prints a go/no-go table.
    - relationship_audit_keys.py: Extracts and prints the set of composite keys
      used in each table to manually verify overlaps.

  validation/temporal_validation/
    - validate_simulator_temporal_contract.py: Verifies that all cleaned task
      records satisfy the temporal contract expected by the simulator: start_time
      < end_time, non-negative duration, no future-dated records relative to the
      dataset epoch.

ALL of the above: SAFE TO DELETE. The dataset is finalized and stable. Rerunning
these checks would produce the same results. The official test_environment.py
and test_machine_state.py in tests/ enforce the runtime data contracts.

================================================================================
  SECTION 7 — analysis/ FOLDER (ENTIRE FOLDER)
================================================================================
The analysis/ folder contains statistical and distributional study scripts that
were used to understand workload characteristics before deciding on simulator
parameters.

  analysis/resource_analysis/
    - analyze_planned_vs_observed_resources.py: Reads both batch_task (planned
      CPU/memory) and batch_instance (actual measured CPU/memory) and computes
      planned-to-actual ratios. Prints histograms and percentile tables.
    - analyze_resource_relationships.py: Correlation analysis between plan_cpu,
      plan_mem, duration, and observed (cpu_avg, mem_avg). Saves a scatter-
      plot matrix or prints correlation coefficients.
    - audit_task_identity.py: Checks whether task_name uniquely identifies a
      task or whether the same name appears with different resource requests.
      Saves task_identity_audit_examples.csv and task_identity_audit_summary.csv.
    - task_identity_audit_examples.csv: Generated output of audit_task_identity.py
      (11 KB). Example rows where task identity was ambiguous.
    - task_identity_audit_summary.csv: Generated summary output of the same script
      (389 bytes). Aggregated statistics about identity conflicts.

  analysis/telemetry_analysis/
    - analyze_telemetry_intervals.py: Computes the distribution of gaps between
      consecutive machine_usage telemetry records per machine. Identifies machines
      with very sparse or very dense reporting.
    - analyze_telemetry_intervals_duckdb.py: DuckDB-accelerated version of the
      same analysis (processes larger chunks faster). Supersedes the pandas version.
    - inspect_telemetry_timestamps.py: Reads the first and last timestamps from
      machine_usage and prints the epoch range. Simpler companion to the interval
      analysis.

  analysis/workload_analysis/
    - analyze_workload_characteristics.py: Comprehensive 16 KB analysis of the
      preprocessed task pool: value-count distributions, duration deciles, CPU
      request distributions, memory request distributions, and correlation matrix.
      Most comprehensive of the workload study scripts.
    - analyze_workload_percentiles.py: Computes and prints CPU, memory, and
      duration at the 50th, 75th, 90th, 95th, and 99th percentiles for the
      task pool. Used to set workload profile boundaries.
    - analyze_workload_regimes.py: Groups tasks into "light", "medium", and
      "heavy" regime bins based on CPU and duration percentile cutoffs, computes
      regime membership counts and resource distributions. 18 KB.

ALL of the above: SAFE TO DELETE. The analysis findings were used to calibrate
the RL environment parameters and workload profiles. Those decisions are now
locked into the training scripts and scenario configuration files.
